Sicoob

Este documento orienta o suporte na configuração do portador Sicoob (código 756) para clientes que vão usar a cobrança via API do Sentus (API Cobrança Bancária V3).

Visão geral​

  • Autenticação: OAuth2 client_credentials com mTLS. O token é pedido com o client_id da aplicação e o certificado digital do cooperado.
  • Todas as chamadas usam mTLS, não só o token. O certificado (.crt e .key) é obrigatório no portador.
  • O token vale poucos minutos (o Sicoob orienta emitir dentro de uma janela de 5 minutos).
  • Todas as chamadas levam Authorization: Bearer <token> e o header client_id.
  • Operações suportadas no Sentus:
OperaçãoEndpoint Sicoob (base /cobranca-bancaria/v3)
Emitir (registrar) boletoPOST /boletos
Consultar boletoGET /boletos?numeroCliente&codigoModalidade&linhaDigitavel
Listar boletos do pagadorGET /pagadores/{numeroCpfCnpj}/boletos
Alterar boletoPATCH /boletos/{id}
Baixar boletoPOST /boletos/{id}/baixar
Extrato de conta correnteGET /conta-corrente/v4/extrato/{mes}/{ano} (API Conta Corrente)
Webhook de cobrança (Sicoob → Sentus)POST /sicoob/webhooks/cobranca/{tenantId}/{portId}/{portAuth}
Identificador do boleto

O {id} é o nosso número. A consulta usa a linha digitável.

Sem PDF pelo banco

O Sentus não pede PDF ao Sicoob (envia gerarPdf=false). O boleto é impresso a partir dos dados retornados no registro.

Pré-requisitos (cliente)​

Sem estes itens não é possível configurar

O cliente precisa ser cooperado Sicoob, ter contrato de cobrança na cooperativa e um certificado digital A1 ICP-Brasil (e-CNPJ, ou e-CPF para pessoa física).

  1. Contrato de cobrança com a cooperativa. Sem ele o Sicoob responde "Associado não possui cadastro de Beneficiário".
  2. Boleto híbrido (com Pix): pedir à cooperativa a habilitação no cadastro. Sem ela o Sicoob responde "Beneficiário não habilitado para utilizar o Pix".
  3. Certificado digital A1 padrão ICP-Brasil, emitido para o CNPJ do cooperado (ou CPF, se PF), com Uso Avançado da Chave = Autenticação de Cliente (1.3.6.1.5.5.7.3.2).
  4. Cadastro no Portal Developers Sicoob e aplicativo de produção com a API Cobrança Bancária.
  5. Acesso ao App Sicoob (Mobile Banking) do titular da conta, para aprovar a criação do aplicativo.

Passo a passo no Portal Developers​

  1. Cadastro: menu Cadastro → preencher dados → confirmar o e-mail.
  2. Preparar o certificado: exportar só a chave pública do certificado em .pem, .crt ou .cer (ver abaixo).
  3. Criar o aplicativo: Meus Aplicativos > Nova Aplicação.
    • Entrar com cooperativa, conta-corrente (ou chave de acesso) e senha do App Sicoob para confirmar.
    • Digitar o código de verificação que chega no App Sicoob.
    • Percorrer as etapas Informações, Segurança, APIs, Confirmação, Aplicativo: marcar a API Cobrança Bancária (e Conta Corrente, se for usar extrato) e anexar o certificado público.
  4. Pegar o client_id e as URLs de produção em Meus Aplicativos.
Atenção
  • Anexe só a chave pública no Portal. Nunca envie a chave privada ao Sicoob: se enviar, o Sicoob exige gerar um novo par e o cliente pode ter de pagar novo certificado.
  • O arquivo .pem deve ter só BEGIN CERTIFICATE. Se tiver BEGIN RSA PRIVATE KEY, remova.
  • Se o certificado estiver em .pfx: openssl pkcs12 -in certificado.pfx -nokeys -out certificado.pem.
  • Com mais de um preposto na conta, qualquer alteração no aplicativo volta ao fluxo de aprovação (status Pendente) até aprovarem no App Sicoob ou no Sicoobnet Empresarial.
  • Se o cadastro do cliente estiver desatualizado, o Portal pede atualização. Se a criação demorar demais, aparece "Erro ao obter os metadados do cooperado": é preciso recomeçar.
  • Não chegou o código no App? Em Notificação do app, desligue e ligue as notificações (e confira as do celular).
  • Restrição por IP (opcional): se o cliente ativar, cadastre o IP público de saída do servidor do Sentus (incluindo contingência). IP de outra origem é recusado.

Número do cliente

O "número do contrato" é o mesmo código do cliente/cedente que aparece no portal de atendimento da cooperativa. O gerente informa. Se o Sicoob responder "O número do contrato deve ser o mesmo número do cliente", o valor do Convênio está errado.

Certificado no Sentus

O Sentus lê do zip do portador o arquivo com .crt e o com .key no nome. Monte o zip com somente esses dois arquivos (PEM). O certificado tem de ser o mesmo anexado ao aplicativo no Portal.

Parâmetros (params)​

Exemplo para Produção:

api.ambiente=PRODUCAO
api.url.auth=https://auth.sicoob.com.br/auth/realms/cooperado/protocol/openid-connect/token
api.url.cob=https://api.sicoob.com.br/cobranca-bancaria/v3/boletos
api.url.cobConsulta=https://api.sicoob.com.br/cobranca-bancaria/v3/boletos
api.url.cobListar=https://api.sicoob.com.br/cobranca-bancaria/v3/pagadores/{id}/boletos
api.url.cobAlt=https://api.sicoob.com.br/cobranca-bancaria/v3/boletos/{id}
api.url.cobBaixa=https://api.sicoob.com.br/cobranca-bancaria/v3/boletos/{id}/baixar
api.url.extrato=https://api.sicoob.com.br/conta-corrente/v4/extrato/{mes}/{ano}
api.webhookAuth=CHAVE_DEFINIDA_PELO_SUPORTE
api.sentus=true
api.sentus.grantType=client_credentials
api.client_id=COLE_O_CLIENT_ID

Para Homologação (Sandbox), use as mesmas chaves com sufixo Hom e a base https://sandbox.sicoob.com.br/sicoob/sandbox/cobranca-bancaria/v3 (extrato: .../sandbox/conta-corrente/v4/extrato/{mes}/{ano}).

Atenção
  • O Sentus escolhe a URL pela situação do portador: Homologação usa as chaves *Hom; Ativo usa as de produção.
  • {id} é literal: o Sentus troca pelo nosso número (alterar, baixar) ou pelo CPF/CNPJ do pagador (listar). No extrato, {mes} e {ano} são trocados pelo Sentus.
  • No Sicoob o client_id vai também no header de toda chamada. O client_secret não é usado (a segurança é o certificado).
  • O Sentus não envia escopo ao pedir o token (o campo api.sentus.roles não tem efeito no Sicoob). Veja Pendências.
  • Sem api.url.* do ambiente ativo, a operação falha com "URL ... inválida".

Sandbox do Sicoob

No sandbox o Portal fornece um access token pronto e um client_id de teste. Não é o mesmo fluxo de token por mTLS da produção.

Regras do Sicoob que o suporte precisa conhecer​

RegraDetalhe
Propriedades opcionaisA V3 não aceita campo opcional vazio ou nulo: ele deve ser omitido. Senão volta erro 400
numeroContratoCobrancaNão enviar no cadastro de boleto. Se vier errado, erro "Número do contrato de cobrança inválido" (o Sentus não envia)
Valores fixos do SentusEmissão pelo banco (1), distribuição pelo banco (1), aceite true, parcela 1, gerarPdf=false
Limite de chamadasConsultar boleto 20/s, incluir boleto 5/s, alterar 5/s, baixa e 2ª via 10/s, conta corrente 2/s
ExtratoUm mês por chamada (o Sentus divide o período), filtrado por diaInicial/diaFinal e numeroContaCorrente
Datas do webhookChegam em UTC (terminam em Z): converter para Brasília (UTC-3)
MovimentaçõesArquivos JSON de qualquer período de 2 dias dentro de 1 ano; ficam 30 dias para download (o Sentus não usa)

Webhook de cobrança (opcional)​

O evento é a baixa operacional (registro da intenção de pagamento, não a liquidação final). O Sentus recebe em:

POST https://<host-sentus>/sicoob/webhooks/cobranca/{tenantId}/{portId}/{portAuth}
ParâmetroOrigem
tenantIdIdentificador do tenant do cliente
portIdID do portador cadastrado
portAuthValor que o suporte define em api.webhookAuth no params do portador. Precisa ser idêntico ao da URL; se faltar ou diferir, o Sentus rejeita

Cadastro do webhook no Sicoob​

Por API (Cadastrar Webhook, escopo webhooks_inclusao). Informe:

CampoValor
urlA URL acima. Deve ser https, porta 443
codigoTipoMovimento7 (Pagamento / baixa operacional)
codigoPeriodoMovimento1 (Movimento atual, D0)
e-mailE-mail de contato

O cadastro devolve um idWebhook. Também há Consultar Webhooks Cadastrados e Consultar Solicitações de um Webhook (situação 3 = enviado, 6 = erro no envio).

Validação da URL

Ao cadastrar, alterar ou reativar, o Sicoob manda uma notificação de validação ({"idWebhook": 990, "validacaoWebhook": true}). A URL só é aceita se responder 200, 201 ou 204. 202 ou redirecionamento (302) reprovam. Evite redirecionamentos e respostas assíncronas.
